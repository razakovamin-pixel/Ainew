# Админ-панель Ilm al-Rijal — установка и запуск

Админ-панель добавлена **внутрь существующего Cloudflare Worker** — отдельного
сервера поднимать не нужно, всё разворачивается одной командой `wrangler deploy`.

## Что добавлено

| Файл / папка                          | Назначение                                              |
|----------------------------------------|----------------------------------------------------------|
| `migrations/0001_init.sql`             | Схема базы данных D1 (таблицы админки)                   |
| `migrations/0002_seed_transmitters.sql`| Импорт существующих 10 062 передатчиков из `public/transmitters*.json` в D1 |
| `src/admin/*.js`                       | Backend: авторизация, JWT, CRUD, импорт/экспорт, бэкапы  |
| `public/admin/index.html`, `app.js`    | Frontend панели управления (`/admin`)                    |
| `worker.js`                            | Добавлены роуты `/api/admin/*` и `/admin`, счётчики статистики ИИ/поиска |
| `wrangler.toml`                        | Добавлен биндинг D1 `[[d1_databases]]`                   |

**Ничего не удалено.** Публичный сайт, поиск, ИИ-чат и статические JSON-файлы
работают как раньше — админка полностью аддитивна.

## Шаги установки

### 1. Создать базу данных D1

```bash
wrangler d1 create ilm-al-rijal-db
```

Команда выведет `database_id` — скопируйте его в `wrangler.toml`, заменив
`REPLACE_WITH_YOUR_D1_DATABASE_ID`.

### 2. Применить схему

```bash
wrangler d1 execute ilm-al-rijal-db --remote --file=migrations/0001_init.sql
```

### 3. (Опционально) Импортировать существующих передатчиков

Переносит все 10 062 записи из `public/transmitters.json` …
`transmitters5.json` в таблицу `transmitters`, чтобы админка сразу видела
существующие данные:

```bash
wrangler d1 execute ilm-al-rijal-db --remote --file=migrations/0002_seed_transmitters.sql
```

Файл большой (~10 тыс. строк) — выполнение может занять пару минут.
Это не обязательный шаг: без него админка просто стартует с пустой таблицей
передатчиков, и вы наполняете её через `/admin` или импорт JSON/CSV.

### 4. Задать секрет для подписи сессий

```bash
wrangler secret put JWT_SECRET
```

Введите любую длинную случайную строку (например, `openssl rand -hex 32`).

### 5. Деплой

```bash
wrangler deploy
```

### 6. Первый вход

Откройте `https://<ваш-домен>/admin`. Так как пользователей ещё нет, форма
предложит создать первого администратора (логин + пароль от 8 символов).
После создания — обычный вход по этим данным.

## Роли

- **admin** — полный доступ: пользователи, настройки, бэкапы, всё содержимое.
- **moderator** — CRUD по контенту + удаление, просмотр пользователей и журнала действий, импорт/экспорт. Не может менять роли/пароли других пользователей и настройки сайта.
- **editor** — создание и редактирование контента (передатчики, книги, иснады, статьи), без удаления.

## Технические примечания

- **Пароли**: Cloudflare Workers не поддерживает нативный bcrypt — используется
  PBKDF2-SHA256 (100 000 итераций, Web Crypto API), криптографически надёжная
  и общепринятая альтернатива для этой среды выполнения.
- **Сессии**: JWT (HS256), подписанный вручную через Web Crypto, хранится в
  httpOnly-cookie (не читается из JS, защита от XSS-угона сессии).
- **CSRF**: cookie с одноразовым токеном (не httpOnly) + обязательный заголовок
  `X-CSRF-Token` на все изменяющие запросы (double-submit pattern).
- **SQL-инъекции**: все запросы к D1 — параметризованные (`prepare().bind()`),
  без конкатенации пользовательского ввода в SQL.
- **Брутфорс логина**: до 5 неудачных попыток на пару логин+IP за 15 минут,
  затем блокировка на 15 минут; плюс общий rate-limit на уровне Worker.
- **XSS**: весь пользовательский текст экранируется при рендере в
  `public/admin/app.js` (функция `esc()`); Markdown-статьи хранятся как есть и
  рендерятся публичной частью сайта — если вы добавите рендер Markdown → HTML
  на публичных страницах, используйте санитайзер (например, DOMPurify) на
  стороне клиента.
- **Локальная разработка (`wrangler dev`)**: по умолчанию работает по HTTP,
  поэтому cookie не помечаются `Secure` в этом режиме автоматически (проверка
  идёт по протоколу запроса) — в проде на `https://` они всегда `Secure`.

## Дальнейший (необязательный) шаг

Публичные страницы сайта (`public/index.html` и т.д.) сейчас как и раньше
читают статические JSON-файлы — это осознанное решение, чтобы ничего не
сломать при подключении админки. Если позже вы захотите, чтобы публичный
поиск передатчиков брал данные из D1 (т.е. изменения из `/admin` сразу
появлялись на сайте без пересборки), понадобится:

1. Публичный read-only эндпоинт, например `GET /api/transmitters`.
2. Замена участка кода в `public/index.html`, который сейчас делает
   `fetch('/transmitters.json')`, на обращение к этому эндпоинту.

Это отдельная, более рискованная для текущего UI задача — сделайте её вторым
шагом и на копии проекта.
